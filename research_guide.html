1. What the Target Research Page Does

The Target Research (`#research`) interface is Stage 01 (Learn & Ingest) of the AEGIS-AGENT autonomous security assessment workflow. Traditional scanners require blind bruteforce network probes that trigger firewall blocks and generate severe false positives. AEGIS solves this by ingesting architecture context upfront—including Git repository metadata, OpenAPI/Swagger specifications, and staging endpoint URLs—extracting an Abstract Syntax Tree (AST) attack surface before any probe is dispatched.

Stage 01: Ingest Repo AST & OpenAPI Spec Extraction
Stage 02: Red Probe Controlled Syntax Breaker Probes
Stage 03: Sentinel Deterministic Proof-of-Exploit
Stage 04: Fix Agent Automated Patch Synthesis
Stage 05: Auditor Isolated Regression Verification
🛡️ Safe Sandbox Containment Guarantee
All probe delivery, exploit verification, and patch evaluations are strictly bounded to the authorized demo container SEC-LOCAL-8080. When you input a custom staging URL (e.g. your personal portfolio or API deployment), AEGIS automatically maps it safely to the local container without making destructive external network calls or modifying production repositories.

3. Step-by-Step: How to Execute & Obtain Output

Step 01 • Target Selection Fast & Easy
Select a Preset or Enter Your Custom Target

Navigate to http://localhost:3000/#research. Click one of the quick preset chips at the top (such as Session Gateway (JWT Auth) or Auth Microservice). All input fields will automatically populate with realistic configuration.

If using your own target: Click + Custom Target and enter your staging URL (e.g. https://abhi-portfolio-wheat-s.vercel.app). The right-side panel immediately updates with a live notice: (Sandbox Mapped: SEC-LOCAL-8080).

Step 02 • Surface Discovery Ingestion Trigger
Click "Ingest Target & Discover Surface"

Click the green button: Ingest Target & Discover Surface (#btn-research-submit).

What Happens: AEGIS executes POST /api/research/ingest, performs AST pattern mapping, detects the technology stack (e.g. Node.js 20.x • Express 4.19 • SQLite 3 or Go 1.22 • Gin Gateway), assigns a unique Ingestion ID (e.g. RES-AUTH-01), and lists all discovered endpoints with their parameter risk classifications.

Step 03 • Live Simulation Autonomous Multi-Agent
Click "Launch Live War Room →"

Click the purple button: Launch Live War Room → (#btn-research-launch-warroom).

What Happens:

  • The application instantly switches to the War Room (`#war-room`) view.
  • The system initiates a live run via POST /api/runs and polls the backend every 800ms.
  • The progress bar fills from 0% to 100% as the 5 agents coordinate autonomously.
  • Audio synthesizer cues play as each stage completes (Scope verified → Exploit captured → Patch generated → Regression verified).
Step 04 • Inspect Outputs Artifact Delivery
How to View Each Output in the War Room

Once the simulation reaches COMPLETED, four specialized output tabs become available:

Output Tab What You See How to Export / Use It
Finding Dossier
Subtab 1		 Vulnerability summary (CWE-89 / CWE-287), affected component (e.g. POST /api/v1/auth/login), captured database syntax breaker error trace, and call stack. Click Copy cURL to copy the exact HTTP reproduction command. Click Copy Evidence to copy raw traces.
Proposed Fix
Subtab 2		 AI-generated unified diff patch synthesized by the Fix Agent (powered by OpenRouter AI). Shows safe parameterized queries replacing string concatenation. Toggle between Unified Diff and Split Diff views. Click Approve & Apply Patch to simulate merging into master.

Subtab 3		 Independent verification results from the Auditor Agent. Confirms the exploit probe now receives 400 Bad Request while legitimate traffic succeeds. Click Rerun Regression Test to trigger a deterministic re-evaluation anytime.
Raw Execution Logs
Subtab 4		 Full real-time system log stream with millisecond timestamps and multi-agent coordination traces. Inspect exact HTTP request/response codes and safety boundary validations.
