01. Executive Summary & Core Value Proposition

Modern application security is plagued by fragmented workflows: security scanners dump hundreds of raw vulnerability alerts onto developers with zero contextual evidence, while automated AI patching tools frequently introduce syntax errors, break API contracts, or write untested code directly to production without human validation.

AEGIS-AGENT solves this by decomposing security remediation into a 4-agent collaborative war room governed by a strict Workflow Coordinator and Human-in-the-Loop approval gate:

The 5-Stage Roles & Responsibilities

Stage Responsible Agent Function & Safety Boundary
1. Scope Check Scope Controller Enforces target allowlist and explicit operator scope consent. Rejects external domains immediately.
2. Red Agent Controlled Prober Executes only non-destructive, allowlisted CWE test probes against local container fixtures.
3. Sentinel Agent Evidence Reviewer Verifies raw HTTP response signatures. Findings are passed to Fix Agent only if verified.
4. Fix Agent Defensive Synthesizer Synthesizes candidate patch in isolated memory; runs allowlisted tests (e.g. py_compile). Never auto-applies.
5. Auditor Agent Independent Verifier Executes 4-check regression matrix. Strictly independent of Fix Agent internal checks.

3. The Three Demo Scenarios

Scenario A: Golden Path — Successful Remediation (Pass)

STATUS: COMPLETED
  1. Press N to open the modal.
  2. Select Input validation check (CWE-89).
  3. Select Simulation Workflow Outcome: [PASS] Complete.
  4. Check "I confirm scope authorization" and click Start Run.
  5. Watch the flow: Red Agent captures SQL error trace → Sentinel confirms (99% confidence) → Fix Agent synthesizes prepared statement diff → Auditor verifies 4/4 checks → Status becomes COMPLETED.

Scenario B: Guardrail Path — Sentinel Caution (Needs Review)

STATUS: NEEDS REVIEW
  1. Press N and select Authentication check (CWE-287).
  2. Select Simulation Workflow Outcome: [ALERT] Needs Review.
  3. Click Start Run.
  4. Watch the safety halt: Sentinel detects ambiguous reflection. The pipeline halts immediately. Fix Agent and Auditor remain queued. Proves the system doesn't write code without verified evidence!

Scenario C: Regression Detection — Auditor Flag (Failed)

STATUS: FAILED
  1. Press N and select Path traversal check (CWE-22).
  2. Select Simulation Workflow Outcome: [FAIL] Regression Fail.
  3. Click Start Run.
  4. Watch independent verification: Fix Agent proposes a patch, but Auditor's regression suite catches a secondary directory escape bypass. Status becomes FAILED (honest reporting!).

4. Human-in-the-Loop Fix Approval

In the Proposed Fix (Diff) tab (2), click "Approve for Demo". The server updates the run state to APPROVED_FOR_DEMO and turns the badge emerald. Explain to judges: "Approval records human operator consent; it never silently writes code to disk or pushes to GitHub."

5. One-Click Audit Report Download

In the Dashboard & History tab, click "Export Audit Report (JSON)". The browser downloads a complete, sanitized compliance report (AEGIS-Audit-Report-RUN-XXXX.json) with all secret credentials redacted.

Q&A Defense Guide: Winning Answers to Tough Questions

Did your Red Agent actually execute real live network exploits?
Answer: "No, and that is by design for safety and determinism. The Red Agent operates in a controlled sandbox executing predefined, non-destructive test probes against our authorized local test fixture. We strictly reject arbitrary targets and external internet hosts."
Does your Fix Agent rewrite code directly in the user's Git repository?
Answer: "Absolutely not. In enterprise security, unattended code modification is a major risk. Our Fix Agent synthesizes candidate diffs in an isolated memory sandbox and runs allowlisted syntax validation. Human operator approval is strictly required before any change can be applied."
Why not just use a single LLM prompt instead of 4 separate agents?
Answer: "Separation of concerns is critical for security. If the agent that generates the fix also verifies the fix, it suffers from self-confirmation bias. By separating Sentinel (evidence triage), Fix (remediation), and Auditor (independent regression testing), each agent has an isolated, auditable role."
How does your backend connect to the frontend?
Answer: "Our backend is a native, zero-dependency Node.js HTTP server. It serves both the static UI and the REST API (/api/runs) on the exact same port (3000), eliminating CORS issues and ensuring 100% offline hackathon reliability without external npm packages."
